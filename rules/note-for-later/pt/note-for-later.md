# Anote para depois

Quando eu digo “anote para depois” ou peço com outras palavras para lembrar uma ideia, um erro ou uma tarefa, é um pedido para anotar, não para fazer.

Uma anotação é uma linha no arquivo plan.md na pasta onde o trabalho está sendo feito. Se esse arquivo não existir, crie-o.
A linha começa com a data de hoje e o tipo de anotação, seguidos das minhas palavras quase ao pé da letra. Não invente nada por mim: nem a causa, nem a solução, nem o benefício.
Se a anotação já estiver no arquivo, não adicione uma segunda: acrescente a ela a parte nova.

O tipo de anotação é definido pelo sentido do que foi dito, não pela palavra que eu usei para isso:
- erro - o que foi feito é diferente do que se esperava: números errados, uma falha, dados perdidos;
- ideia - algo que ainda não existe: uma função nova, uma melhoria, um ganho de velocidade;
- tarefa - algo que depende só de mim: minha decisão, minha permissão, dinheiro, trabalho feito à mão.
Se o tipo for diferente da minha palavra, faça uma pergunta em vez de decidir em silêncio.

Não faça nada além da anotação. Até eu pedir separadamente para você cuidar disso, não abra arquivos para isso, não procure uma solução por conta própria ou na internet, não escolha uma abordagem e não verifique se já existe algo pronto.
Um pedido curto não significa que a tarefa é pequena: vamos cuidar disso quando eu disser.

Depois de anotar, responda em uma linha que anotou e volte ao trabalho que você estava fazendo antes.
