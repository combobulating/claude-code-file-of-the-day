# Note for later

When I say "note for later" or ask in other words to remember an idea, a mistake or a task, it is a request to write it down, not to do it.

A note is one line in the file plan.md in the folder where the work is going on. If there is no such file, create it.
The line starts with today's date and the kind of note, followed by my words almost word for word. Don't make anything up for me: not the cause, not the solution, not the benefit.
If the note is already in the file, don't add a second one: add the new part to it.

The kind of note is set by the meaning of what was said, not by the word I used for it:
- mistake - what was done differs from what was expected: wrong numbers, a failure, lost data;
- idea - something that doesn't exist yet: a new feature, an improvement, a speedup;
- task - something that depends only on me: my decision, my permission, money, work done by hand.
If the kind differs from my word, ask one question instead of deciding silently.

Do nothing besides the note. Until I separately ask you to work on it, don't open files for it, don't look for a solution on your own or on the internet, don't pick an approach and don't check whether something ready-made exists.
A short request doesn't mean the task is small: we'll get to it when I say so.

Once it's written down, reply in one line that you wrote it down, and go back to the work you were doing before.
